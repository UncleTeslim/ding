# Product roadmap

Ding helps teams publish updates inside their apps while operating their own instance. This is a direction, not a delivery schedule; priorities can change as people use it.

## Now

Prepare the first supported release: reliable Docker installation, clear publishing and embedding guides, security checks, and tested backup recovery. The current product has one shared admin account and a bell/banner widget.

## Next

Fix the friction people encounter when installing and publishing. Build a public changelog page with permanent announcement URLs once the core workflow is established.

## Later, guided by demand

Consider RSS, scheduling, reactions and publishing integrations. Managed hosting is not available. Share hosting needs or feature requests through [Discussions](https://github.com/UncleTeslim/ding/discussions); avoid posting private information.

See [Releases](https://github.com/UncleTeslim/ding/releases) for what has actually shipped and [the security policy](SECURITY.md) for private vulnerability reporting.
